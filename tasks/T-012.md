# T-012 — Move the views folder into `src/`

## Description
The owner wants all of the app's own source (JavaScript and templates) under `src/`, with `public/` staying at the repository root. `views/` moves to `src/views/`. Nothing the user sees changes: the routes, rendered HTML, headers and template names stay the same.

## Acceptance criteria
- [x] `views/` no longer exists at the repository root. `src/views/` holds the same five templates (`layouts/main.liquid`, `pages/home.liquid`, `pages/error.liquid`, `partials/header.liquid`, `partials/footer.liquid`), unchanged and moved with `git mv`, so history follows them.
- [x] `public/` stays at the root, and R3 (static files served at the site root) is unchanged.
- [x] Both the LiquidJS engine (root, layouts, partials) and Express's `views` setting point at `src/views/`, and `res.render('pages/x')` still resolves to `src/views/pages/x.liquid`.
- [x] A test in `test/app.test.js` asserts that `GET /views/pages/home.liquid` and `GET /src/views/pages/home.liquid` return 404 without raw template source.
- [x] `npm test` passes, as do the gate suites (`scripts/test/run-all.sh`).
- [x] `docs/contracts.md` and `docs/architecture.md` name `src/views/` wherever they name the views folder today, and `PROJECT_PLAN.md`'s folder tree shows `/views` under `/src`.

## Out of scope
- Moving `public/` or the planned `database/` folder.
- Renaming, splitting or editing any template.
- Changing the template engine options (`extname`, `outputEscape`, `cache`).
- Editing historical task files (T-001, T-004, and so on) that mention `views/`. They record what was true when they were written.

## Risks / dependencies
- Contract change: `contracts.md` M1 and § 4 name `views/` as the views root. The change is internal, with no public route, response or env var affected.
- `npm run dev` (`node --watch`) restarts only on imported modules, not on templates. With `cache` off outside production, templates are re-read on every render, before and after the move, so nothing changes.
- An open branch that adds or edits templates under `views/` would need a rebase. The only other local branch with unmerged work, `wip/database-setup`, does not touch `views/` (`git diff --stat origin/main...wip/database-setup -- views` is empty).

## Plan
1. `git mv views src/views`.
2. `src/app.js:8`: `const viewsDir = path.join(import.meta.dirname, 'views');`. `rootDir` stays, because the static mount (`src/app.js:32`) still uses it for `public/`. No other line in `src/app.js` changes, so the line numbers cited in `contracts.md` stay valid.
3. `test/app.test.js`: no test pins the folder location. The owner decided on 2026-11-21 that the location is a layout preference, not a behaviour, so it isn't tested. This drops the planned M1 path test, Engineer plan item 1 and Verifier plan item 3. The existing render tests (home page, error page) fail if the engine can't find the templates, and once the old folder is gone there is nothing to fall back to. `test/errorHandler.test.js` copies `app.get('views')`, so it needs no change. Add `test('templates are not served as static files (R3)')`, next to the R3 tests: `GET /views/pages/home.liquid` and `GET /src/views/pages/home.liquid` both return 404, and neither body contains raw Liquid (`{% layout`). This guards against a future change that widens the static mount and exposes templates or server code (Architect plan item 2).
4. `docs/contracts.md`: change every `views/` path that describes the current code to `src/views/`. That covers R1 and R3 blast radius (lines 21, 25), M1 (line 39), § 3.3 (line 74), § 4's configuration line and template table (lines 81, 85–89) and the update-when footer (line 206). The dated verification notes (lines 195, 197, under "How this inventory was built (2026-11-17)") record what was checked on that date, so they keep `views/` and get "(moved to `src/views/` in T-012)" (Architect plan item 1). In § 2's shared **Guarded by** line (`docs/contracts.md:52`), where M1 isn't listed today, add M1 as guarded by the render tests in `test/app.test.js`. Keep the note that its production cache is not guarded (Verifier plan item 2). Add the static-exposure test to R3's **Guarded by**.
5. `docs/architecture.md`: update the Views component row (line 23) and the update-when footer (line 197).
6. `PROJECT_PLAN.md`: move `/views` under `/src` in the folder tree (lines 237–240).
7. Run `npm test` and `sh scripts/test/run-all.sh`, then grep for any `views/` path outside `src/views`, `node_modules` and historical task files.

**Tier:** Risky. It changes a documented contract (M1, § 4) and edits `/docs/*`, which needs unanimous six-agent consensus.
