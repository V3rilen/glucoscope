# T-001 — Bootstrap /docs/ folder

## Description
Per `AGENTS.md` § 0, no feature work happens until `/docs/` is populated. It runs through the Docs Bootstrap Workflow (`AGENTS.md` § 6): the main session drafts each doc, the doc's named owner reviews it first, and only when all 6 agents sign off does any file in `/docs/*` land on `main`.

**The standard:** the goal is not "docs that describe the project" but a living memory complete and accurate enough that a future agent who has read only `/docs/` can commit with high confidence it will not break an existing route, data contract, integration, or behavior. Every doc is held to the **Grounding & Completeness Protocol** (`AGENTS.md` § 6.0) — grounded in real code, no invented facts, exhaustive where it's a contract.

Adopting into an **existing** codebase: the docs are **descriptive** — derived from the code that is already there. A **new** project: they are **forward-looking** and say so.

## Acceptance criteria

All block feature work (must reach `completed`, or `cancelled` as N/A where stated):
- [ ] `T-001.1` (`contracts.md` — exhaustive code-grounded inventory) ⭐
- [ ] `T-001.2` (`architecture.md` — overview, trust boundaries, stack, testing, deployment)
- [ ] `T-001.3` (`data-model.md` — or N/A if there is no datastore)
- [ ] `T-001.4` (`decisions/` skeleton + Architectural Decision Record 0001)
- [ ] `T-001.5` (consensus review + 6 sign-offs + § 6.0 grounding verification)

### Global
- [ ] Every committed doc satisfies the **Grounding & Completeness Protocol** (`AGENTS.md` § 6.0): grounded in real code, no invented facts (`UNKNOWN` where unconfirmed), exhaustive where it's a contract.
- [ ] `contracts.md` is complete enough that an agent reading only `/docs/` can identify every route/contract/integration its change could break.
- [ ] No unreplaced `[insert … here]` placeholders in committed docs.
- [ ] The six sign-offs are recorded in the `## Review` section of `T-001.5`.
- [ ] Adopted project only: every file that was in `docs/` before adoption has been folded into the reviewed docs or moved out of `docs/`, and any file moved out of `docs/` before adoption (`contracts.old.md`, `docs-readme.old.md`) is deleted (`AGENTS.md` § 0 Step 3).

## Risks / dependencies
- Drafting needs enough project context to be accurate. If unsure, ask the owner — do not invent facts.
- The bootstrap blocks feature work. On an existing codebase `contracts.md` is the expensive part; budget for it.

## Notes
This is the **mandatory first task** for every repo using this starter.
