# T-001.3 — Write `data-model.md`

**Parent:** [T-001](./T-001.md) · **Owner:** data-engineer

## Description
Document the schema for `PostgreSQL`: **every** table/collection, indexes, foreign keys, personally identifiable information classification, and the migration approach. This is a **contract-critical** doc: a future agent must be able to change the schema without breaking a dependent query, migration, or consumer using only this file + `contracts.md`. Held to the Grounding & Completeness Protocol (`AGENTS.md` § 6.0) — exhaustive and code-grounded, not a sample.

**No datastore?** If the project stores no data (no database, no persisted files with a schema), do not write the file. Set this task to `cancelled`, record "N/A — <reason>" in Notes, and say so in `contracts.md` under Data contracts. Reopen it the day a datastore is added.

## Acceptance criteria
- [x] `/docs/data-model.md` exists.
- [x] Lists **every** table/collection (not a sample) with columns, types, indexes, and foreign keys — grounded in the actual schema/migrations, with the source path cited. If greenfield, marked **forward-looking**. For column-level detail on a large schema, this doc **may point to a reproducible schema dump / migrations directory** rather than hand-copying — reserve hand-authored prose for what a dump can't capture (PII classification, consumers/blast radius, migration sequencing). The pointer must be exact and reproducible.
- [x] Every table/column entry is reconciled against the real schema (migrations dir / ORM models / live schema dump). The verification method is recorded in the doc.
- [x] Marks every personally identifiable information column and its protection.
- [x] Documents migration tooling, naming convention, reversibility rules, deploy sequencing, and backfill expectations — i.e. **how to change the schema safely**.
- [x] For each table, notes the known consumers / blast radius (which code paths, queries, or contracts depend on it) so a future change can reason about what it might break.
- [x] Any fact not confirmable from code or the human is written `UNKNOWN — needs human confirmation`, never guessed.
- [x] Includes an "update-this-doc-when" footer naming the schema/migration paths that require this doc to be updated.
- [x] All 6 agents have signed off (recorded in `T-001.5`).
