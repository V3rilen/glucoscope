# T-004 — Test harness and tests for the scaffold

## Description
There are no application tests today, so no contract in `docs/contracts.md` is guarded by a test, and `AGENTS.md` § 8 ("no commit without passing automated tests") can't be met for app code. **The owner decided on 2026-11-17 (T-001) that this task blocks all feature work.** Opened by the T-001 docs bootstrap.

## Acceptance criteria
- [x] `npm test` runs every test with the built-in `node:test` runner. No new test dependency is added unless a reviewed plan justifies one.
- [x] The tests run in CI by filling the project-checks slot in `.github/workflows/checks.yml`. This is **Risky tier** (it touches `.github/`) and must be named to the owner in the PR summary.
- [x] The tests import `src/app.js` without `listen` and need **no network and no real database**. The task chooses how to substitute the pool, which `src/models/db.js` builds when it is imported.
- [x] Cases:
  - [x] `GET /` → 200 HTML
  - [x] `GET /health` → 200 `{"status":"ok"}` with a faked healthy pool, and 503 `{"status":"unavailable"}` with a faked failing pool
  - [x] An unknown path and `POST /` → 404 HTML error page with the exact public message
  - [x] A thrown error → 500 with the exact public message
  - [x] With `NODE_ENV=production`, the stack is **not** rendered (the security negative case)
  - [x] `Cache-Control: private, no-store` is present on pages, `/health` and error pages, and **absent** on `/css/styles.css`
  - [x] No `X-Powered-By` header
  - [x] `trust proxy` is set only when `NODE_ENV=production`
  - [x] Template output is escaped (for example a 404 path containing `<script>` is escaped in the development stack trace)
  - [x] `OPTIONS /` → 200 with `Allow: GET, HEAD`; `GET /css` → 301 to `/css/`
  - [x] A malformed or oversized urlencoded body → a 4xx error page with `That request couldn't be processed.`
  - [x] An error whose `err.status` is outside 400–599 → 500
  - [x] `headersSent` → the handler delegates instead of rendering
- [x] The error-throwing cases use a test-only app or router built around the exported middleware. **Production routes are not changed** to make errors testable.
- [x] **No dependence on test order.** `src/app.js:9` reads `NODE_ENV` once, at import time, while `errorHandler.js:27` reads it on every request. So the production-mode cases run in their own process or test file, and the pool fake is isolated in the same way.
- [x] Every "Guarded by: none — T-004" in `docs/contracts.md` is replaced with the covering test file. This is a `/docs` edit, so it needs 6-agent consensus.
- [x] `docs/architecture.md` § 6 is updated from "current state" to the real harness.
- [x] Every error page, including body-parser 400/413/415, carries `Cache-Control: private, no-store` (added 2026-11-18 by the owner's choice of Decision 1 A). The test's failing run before the fix is recorded below.

## Out of scope
- DB integration tests (they come with the first table, T-005)
- End-to-end browser tests

## Plan (v2, 2026-11-17) — Tier: Risky

Risky because it touches `.github/` and `/docs/*`. If Decision 1 is A, it also changes a documented contract (§ 3.3 error responses). v1 was reviewed by all five reviewers (see `## Review`), and this version folds in every item.

**Found while planning** (a probe in the scratchpad, against the code at `489b198`):
- **Body-parser error pages carry no `Cache-Control`.** This affects a rejected form `POST`: oversized → 413, unsupported charset → 415, and a body that claims gzip but isn't → 400.
  - The parser (M6) runs before the header middleware (M7), and its errors go straight to the error handler.
  - Static-file 404s (`/%E0`, `/css/%00x`, `/..%2f..%2fpackage.json`) do carry it. Static 5xx errors (for example running out of file handles, `EMFILE`) would not (Architect, Engineer).
  - So `contracts.md` I3 is false as written. Impact is low: in production those pages show only the generic message.
- **The DB fake needs no production code change.** `t.mock.method(pg.Pool.prototype, 'query', …)` affects `db.js`'s pool. Verified by the probe and by the Engineer in `node_modules`.
- **`fetch` percent-encodes `<`, so it can't test escaping.** `node:http` sends the raw path; the probe confirmed the 404 page escapes it.
- **A hook registered by a file loaded with `node --import` runs after every test in each test file's process.** Probe confirmed.

**Files.**
1. **`package.json`:** add `"test": "node --import ./test/setup.js --test \"test/**/*.test.js\""`. No new dependency. Each file runs in its own process (the default).
2. **`test/setup.js`** (loaded into every test process):
   - **Tripwire:** mocks `pg.Client.prototype.connect` to record the call and reject. Every real DB path (`pool.query`, `pool.connect`, a direct `Client`) goes through it, and nothing touches the network.
   - A global `afterEach` **fails the test** if the tripwire was hit. A throw alone isn't enough, because `checkConnection` swallows errors and would quietly return 503.
3. **`test/helpers/db.js`:** `fakeDb(t, 'healthy' | 'failing' | handler)` mocks `pg.Pool.prototype.query` (one mock, restored by `t.mock`). A handler gets `(text, params)`, and its calls are recorded.
4. **`test/helpers/server.js`:**
   - Starts an app on `127.0.0.1:0`. After the tests, `closeAllConnections()` and then `close()`.
   - `request(method, path, {headers, body})` uses `node:http` with `agent: false`.
   - Socket errors that arrive after the response (`EPIPE`/`ECONNRESET` on 413) are ignored.
5. **Every test file** sets `process.env.NODE_ENV` explicitly before its dynamic `import()` of the app, and restores it in `after`. A shell with `NODE_ENV=production` can't change the results.
6. **`test/app.test.js`** (the real app, `NODE_ENV=test`):
   - `GET /` → 200 HTML. The § 4 template contracts:
     - `<title>Home | Glucoscope</title>`, `lang="en"`, `nav aria-label="Main"`
     - the footer disclaimer, the `/css/styles.css` link
   - `HEAD /` → 200.
   - `/health`: healthy → 200 `{"status":"ok"}`; failing → 503 `{"status":"unavailable"}`, with no error detail in the body.
   - `GET /nope` and `POST /` → 404, heading `404: Page not found`, the exact public message (compared in Liquid's escaped form, `couldn&#39;t`), and the "Back to home" link.
   - `GET /<script>x</script>`: the stack is shown, the path is escaped, and no raw `<script>x` appears.
   - Parser errors show `That request couldn't be processed.`:
     - oversized → 413
     - unsupported charset → 415
     - claims gzip but isn't → 400 (the "malformed" case; with `extended: false` a merely odd body doesn't error)
   - `Cache-Control: private, no-store` on `/`, `/health`, the 404, and the 400/413/415 pages. On `/css/styles.css` it is `public, max-age=0`, **not** `no-store`.
   - No `X-Powered-By` on any of the above, including static and parser errors.
   - `OPTIONS /` → 200, with `Allow` exactly `GET, HEAD`. `GET /css` → 301 to `/css/`.
   - `trust proxy` is off.
   - **I6:** `http.Server.prototype.listen` is mocked before the import and never called.
7. **`test/app.production.test.js`** (`NODE_ENV=production` before import):
   - the 404 and 413 pages show no stack and no `Not found:` text
   - `trust proxy === 1`
   - still `private, no-store`
8. **`test/errorHandler.test.js`:** a **test-only** app built around the exported `notFound` / `errorHandler`. It borrows the real app's views and engine; a test asserts `app.engines['.liquid']` is a function, so a change in Express fails loudly. Production routes are unchanged. Cases:
   - thrown error and rejected async → 500, exact message, logged
   - statuses 302, 600 and none → 500; 418 → 418 with the 4xx message
   - **the production-mode 500 has no stack** (moved here from v1's production file, since no real route can throw)
   - `headersSent` → `next(err)`, with no render
   - `errorHandler.length === 4` (I5)
   - the error page carries `Cache-Control` (Decision 1)
9. **`test/db.test.js`:**
   - `query(text, params)` passes both to `pool.query` unchanged and lets errors propagate.
   - `checkConnection` returns true / false and logs only `err.message`.
10. **`.github/workflows/checks.yml`:** in the existing required `shell scripts (lint + test)` job, fill the project-checks slot. A new job or a matrix would rename or skip the required check.
    - `actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0`. Verified: the `v7.1.0` tag points to this commit, and it is in `actions/setup-node`'s `main` history, not a fork.
    - `node-version: '22.9.0'`, the `engines` floor that `--env-file-if-exists` needs.
    - **`package-manager-cache: false`.**
    - `npm ci --ignore-scripts` then `npm test`. No `${{ }}` in `run:`, and permissions unchanged.
11. **`/docs` (6-agent consensus):**
    - `contracts.md`:
      - Each "Guarded by" names its test.
      - Entries that can't be tested here say so honestly: `PORT` (read only by `server.js`, startup glue, not tested; T-006 deploy smoke check), `DATABASE_URL` (T-005), the template cache (not observable).
      - § 3.3 and I3 updated per Decision 1; § 7.3 has a `test` script.
    - `architecture.md` § 6: the real harness.
    - `architecture.md` § 7:
      - The CI step is in place.
      - Branch protection is **confirmed**: ruleset `protection-main`, both checks required from the GitHub Actions app, up to date before merge, PR required, no force-push or deletion, no bypass. Read through the GitHub API on 2026-11-17.
      - A PR runs its own `checks.yml`, so a PR could drop `npm test`. The control for that is Risky-tier review of `.github/` plus your review.
12. **Tasks:**
    - T-006: tick branch protection, with the API evidence in its log. Add "which Node version production runs" to its scope.
    - New T-007: `AGENTS.md` lines 7 and 218 point to a README "Setup" section that doesn't exist. This PR doesn't touch `AGENTS.md` or the README.

**Decision 1 for the owner: the `Cache-Control` gap.**
- **A (recommended):** fix it here with **one line in `errorHandler`**: `res.set('Cache-Control', 'private, no-store')` before rendering.
  - Every error page gets it, whichever middleware raised the error. That covers parser 400/413/415 and static 5xx, so I3 becomes true without depending on middleware order. The middleware order is unchanged.
  - This adds a criterion: *"Every error page, including body-parser 400/413/415, carries `Cache-Control: private, no-store`."*
  - It's a bug fix, so the test is committed first and its **failing** run is recorded before the fix.
- **B:** tests only. Record 400/413/415 as an exception to I3, mark that part of the `Cache-Control` criterion superseded, and open a task for the fix.

**Decision 2: record branch protection in this PR's docs edit (recommended).** Otherwise it waits for T-006.
