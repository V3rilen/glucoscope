# T-004 — Test harness and tests for the scaffold

## Description
There are no application tests today, so no contract in `docs/contracts.md` is guarded by a test, and `AGENTS.md` § 8 ("no commit without passing automated tests") can't be met for app code. **The owner decided on 2026-11-17 (T-001) that this task blocks all feature work.** Opened by the T-001 docs bootstrap.

## Acceptance criteria
- [ ] `npm test` runs every test with the built-in `node:test` runner. No new test dependency is added unless a reviewed plan justifies one.
- [ ] The tests run in CI by filling the project-checks slot in `.github/workflows/checks.yml`. This is **Risky tier** (it touches `.github/`) and must be named to the owner in the PR summary.
- [ ] The tests import `src/app.js` without `listen` and need **no network and no real database**. The task chooses how to substitute the pool, which `src/models/db.js` builds when it is imported.
- [ ] Cases:
  - [ ] `GET /` → 200 HTML
  - [ ] `GET /health` → 200 `{"status":"ok"}` with a faked healthy pool, and 503 `{"status":"unavailable"}` with a faked failing pool
  - [ ] An unknown path and `POST /` → 404 HTML error page with the exact public message
  - [ ] A thrown error → 500 with the exact public message
  - [ ] With `NODE_ENV=production`, the stack is **not** rendered (the security negative case)
  - [ ] `Cache-Control: private, no-store` is present on pages, `/health` and error pages, and **absent** on `/css/styles.css`
  - [ ] No `X-Powered-By` header
  - [ ] `trust proxy` is set only when `NODE_ENV=production`
  - [ ] Template output is escaped (for example a 404 path containing `<script>` is escaped in the development stack trace)
  - [ ] `OPTIONS /` → 200 with `Allow: GET, HEAD`; `GET /css` → 301 to `/css/`
  - [ ] A malformed or oversized urlencoded body → a 4xx error page with `That request couldn't be processed.`
  - [ ] An error whose `err.status` is outside 400–599 → 500
  - [ ] `headersSent` → the handler delegates instead of rendering
- [ ] The error-throwing cases use a test-only app or router built around the exported middleware. **Production routes are not changed** to make errors testable.
- [ ] **No dependence on test order.** `src/app.js:9` reads `NODE_ENV` once, at import time, while `errorHandler.js:24` reads it on every request. So the production-mode cases run in their own process or test file, and the pool fake is isolated in the same way.
- [ ] Every "Guarded by: none — T-004" in `docs/contracts.md` is replaced with the covering test file. This is a `/docs` edit, so it needs 6-agent consensus.
- [ ] `docs/architecture.md` § 6 is updated from "current state" to the real harness.

## Out of scope

- End-to-end browser tests
