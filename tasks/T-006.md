# T-006 — Deployment and rollback procedure

## Description
`docs/architecture.md` § 2 and § 7 and `docs/data-model.md` § 1 record the deployment facts as `UNKNOWN`, because nothing in the repo shows them. **The owner decided on 2026-11-17 (T-001) that there is no production deploy until this task lands.** Opened by the T-001 docs bootstrap.

## Acceptance criteria
- [ ] Record the Cloudflare-to-origin link (Tunnel or proxied DNS with port forwarding), the SSL mode, and whether the origin accepts only Cloudflare traffic. If the origin is reachable directly, address the `X-Forwarded-*` forgery risk created by `trust proxy`.
- [ ] Record Cloudflare cache and WAF rules, including that they must not cache pages and must not block xDrip+ POSTs to `/api/v1/*` (`PROJECT_PLAN.md` § 8).
- [ ] Record that PostgreSQL listens on localhost only, the app role's privileges, and whether Express-to-PostgreSQL TLS is needed.
- [ ] Record the process manager (system service or PM2), how `NODE_ENV=production` and the `.env` file are provided, and where logs go.
- [ ] Record the release steps and a **rollback procedure that has been tested**, including migrations (depends on T-005).
- [ ] Record backups: a scheduled `pg_dump`, stored off the machine, with at least one test restore.
- [ ] Record whether the CI checks are required on `main` (branch protection).
- [ ] Record any uptime monitor pointed at `/health`, and where logs are kept and for how long.
- [ ] The `/health` hang when the DB host is unreachable (no `connectionTimeoutMillis`; `PGCONNECT_TIMEOUT` has no effect) is a **code change**. It needs its own plan and tier, and a regression test showing that an unreachable DB returns 503 within a bounded time. It may be split into its own task.
- [ ] Update `docs/architecture.md` and `docs/data-model.md`, replacing each `UNKNOWN`. This is a `/docs` edit, so it needs 6-agent consensus.
