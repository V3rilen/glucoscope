# T-008 — Guard the `npm test` CI step

## Description
A pull request runs its **own** `.github/workflows/checks.yml`, so a PR that deletes the `npm test` step still passes the required `shell scripts (lint + test)` check. The gate scripts are protected, because `ci-pr-checks.sh` runs the **target** branch's copy, but the test step is not. Today the only control is the owner's review, which is a self-review in practice (0 required approvals). Raised by the Architect in the T-004 build review (`docs/architecture.md` § 7, "Limit").

## Acceptance criteria
- [ ] A check that runs from the **target** branch (for example in `scripts/ci-pr-checks.sh`, or a test it calls) fails a PR whose `checks.yml` no longer runs `npm test` in the required job.
- [ ] It has a fixture test in `scripts/test/`, like the other gates.
- [ ] `docs/architecture.md` § 7's "Limit" is updated. This is a `/docs` edit, so it needs 6-agent consensus.

## Risks / dependencies
- Touches `scripts/`, so it's Risky tier. A gate change takes effect from the next PR after it merges.
