# T-008 — Guard the `npm test` CI step

## Description
A pull request runs its **own** `.github/workflows/checks.yml`, so a PR that deletes the `npm test` step still passes the required `shell scripts (lint + test)` check. The gate scripts are protected, because `ci-pr-checks.sh` runs the **target** branch's copy, but the test step is not. Today the only control is the owner's review, which is a self-review in practice (0 required approvals). Raised by the Architect in the T-004 build review (`docs/architecture.md` § 7, "Limit").

## Acceptance criteria
- [ ] A check that runs from the **target** branch (for example in `scripts/ci-pr-checks.sh`, or a test it calls) fails a PR whose `checks.yml` no longer runs `npm test` in the required job.
- [ ] It has a fixture test in `scripts/test/`, like the other gates.
- [ ] `docs/architecture.md` § 7's "Limit" is updated. This is a `/docs` edit, so it needs 6-agent consensus.

## Risks / dependencies
- Touches `scripts/`, so it's Risky tier. A gate change takes effect from the next PR after it merges.

## Plan
- Add a target-branch workflow-policy check to the trusted PR gate. Read the target revision's `.github/workflows/checks.yml` as the trusted policy source and the PR-head revision's file as the artifact under test; read both through explicit Git object lookups, never the mutable worktree.
- Define a narrow, fail-closed lexical YAML subset: both `target_sha:.github/workflows/checks.yml` and `head_sha:.github/workflows/checks.yml` must resolve to exactly one regular Git blob before `git cat-file`; each must be LF-only with no tabs, have `jobs:` at column 0, exactly one `scripts:` job at two-space indentation, and exactly one `- name: app tests (npm test)` step at six-space indentation inside that job. The named step must contain the exact approved command sequence, and the complete PR-head `scripts` job must be byte-for-byte identical to the trusted target revision's job. Top-level workflow `env` and `defaults` are forbidden because they can change npm/shell execution outside the job block; unrelated jobs remain outside this comparison. Missing, malformed, duplicated, reordered, ambiguous, or changed protected wiring fails closed, and workflow bytes are never printed to logs.
- Protected-job changes use two pull requests after T-008 lands: first update the trusted target-branch policy to permit one reviewed prospective job digest while the workflow remains unchanged; after that policy lands, change the workflow to that exact approved job. This prevents a pull request from approving its own protected-job rewrite.
- Add deterministic fixture coverage in `scripts/test/test-ci-pr-checks.sh`, discovered by `scripts/test/run-all.sh`: `test_target_gate_rejects_pr_workflow_without_npm_test` (criterion 1, and a regression that fails before the fix); `test_run_all_discovers_ci_pr_workflow_fixtures` (criterion 2); `test_architecture_documents_workflow_guard` (criterion 3); a positive exact-current-workflow case; and named negatives for missing/wrong/duplicate `scripts` jobs, test in another job, test-before-ci, `npm run test`, altered commands, comment/echo decoys, unsupported YAML forms, and missing/altered `npm ci --ignore-scripts`.
- Update `docs/architecture.md` § 7 to replace the documented limitation with the implemented protection and its remaining scope.
- Run shell lint, all fixture suites, and `npm test`; record the Risky build review and regression-safety result in this task.

**Tier:** Risky — changes `scripts/`, `.github/` policy enforcement, and `/docs/`.

**Out of scope:** changing the required check name, moving app tests to another job, protecting unrelated workflow behavior, or changing the application test suite itself.
